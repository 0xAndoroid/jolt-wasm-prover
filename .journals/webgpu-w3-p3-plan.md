## Lever 1 — stage-2 sumcheck (`prove_stage2` `core/fold/stages.rs:103`, prover `relation_range_image/`)
- What: per fold level, one degree-3 sumcheck fusing the range-image norm claim + relation claim + structured linear terms over the digit witness `w` (compact 3-bit → `Vec<E>`), `num_vars = coefficient_bits + lane_bits` (24/21/20/19/18/17 at 2^18 → 119 rounds). Host does Gruen split-eq, `polys_from_terms` → `combine_polys` → `trim_trailing_zeros` → absorb; challenge = `sample_grinded_sumcheck_challenge` (Blake2b + ≤10 grind hashes). Round poly is unique ⇒ any exact GPU algorithm is bit-identical; trimming/SkipLinear stay host-side.
- Two weight modes, both needed: levels 1–2 (`QuotientLift`, 451 mini ms = 55 %) = `QuotientFactored` — pair weight `alpha[coef]·lane_w[lane]` (two tiny tables), two-round bivariate skip built in `new` from compact digits (72.5 + 15.7 ms), partial-lane coefficient/lane modes, sparse `AdditionalRelationTerms`; levels 3–6 (`ReducedEvaluation`/L2, 372 ms = 45 %) = `ReducedDense` — n-sized `DenseRelationWeights` folded alongside `w`, round 0 on compact digits via `CompactPairFoldLut`, no prefix. Metal ports QF only (RD → `direct_relation_cpu_fallback`); we should do RD first (simpler: two dense tables + eq).
- Per-round CPU curve (mini ms), level 24: `new` 72.5 · rounds 11.1 89.8 55.8 25.0 13.4 14.9 23.9 14.7 5.5 3.8 4.3 3.1 · then ≤ 2.2 each. Eligible work (rounds with table ≥ 2^12 + `new`/prefix): 338+65+75+105+51+37 = **670 mini = 299 MBP ms**; residual CPU tails ≈ 68 ms.
- GPU cost: dependent RUN_SEQ trips 12+9+8+7+6+5 = **47** + 6 prefix/setup + 6 uploads (compact digits 6 MiB @L1; dense weights 16 MiB @L3; linear terms) + 6 handoff downloads (2^12·16 B) ≈ 65 ops × 1.5 ms ≈ 100 ms + compute ≈ 15 M fp128 mul ≈ 10 ms → **≈ 110 ms** ⇒ net ≈ 0.19 s. 2^20: +2 rounds/level (59 trips), tables ×4 → CPU 1.1–1.5 s, GPU ≈ 160 ms.
- Per-round GPU op (one RUN_SEQ, mirrors W2 `field.wgsl`): fused kernel = fold `w` (and dense weights / linear table) by `r` into the ping-pong half + evaluate pairs → partials `virt[3]` (or `[2]` SkipLinear — host decides, kernel always emits 3) + `rel[3]` (+ additional-terms partials) weighted by `e_first[j&mask]·e_second[j>>k]`; 1-workgroup reduce; 96 B inline readback. Params inline: `r`, mode flags, live_pairs, coef/lane bits; eq tables inline (≤ 2·2^12·16 B) as W2 does; QF alpha/lane tables inline (≤ 2^12). Handoff: download the folded `w` (+ weights) at 2^12 entries → CPU `WitnessState::FoldedSuffix` resumes.
- Seam (**patch 0008** `akita-relation-range-device.patch`, akita-prover only, ~150 lines + 0007-style wrapper ~350): `relation_range_image/device.rs` — `RelationRangeDevice::open(job) -> Option<Result<(Box<dyn RelationRangeSession>, rounds)>>` with job = {compact digits view, basis, domain_len, live_pairs, mode QF{alpha, lane_w}|RD{dense weights}, linear terms (dense or structured), additional sparse weights, coefficient_bits, lane_bits}; `session.round(round, prev, e_first, e_second, alpha/lane tables, out) `→ terms bytes; `session.tables()` at handoff. Hook: `compute_current_round_poly_from_state` (`round_flow.rs:22`) → device terms feed the existing `polys_from_terms`/`combine_polys`; `ingest_*_challenge` → device fold, host still folds `linear_terms` (structured, `evaluation_trace.rs:843-913`) and `split_eq.bind`. Process-global `set_relation_range_device` like 0007; parity shadow `set_relation_range_parity_rounds`. jolt side: install with the W2 device in `engine::install_digit_range_device`; feature `relation-range-device`.
- Linear terms are the design unknown: `PreparedLinearLaneKind::{Dense(E), Packing{factor,values}, Sparse, Zero}` per lane; a dense materialization is n×16 B (256 MiB @L1 2^18) — Metal expands them on device (`direct_relation_setup_source`/`sparse_source` kernels) and folds per round (`linear_fold`). U0 measures the kind/len per level; fall back to in-kernel expansion (U6) or RD-only scope if dense does not fit.
- Units (atomic, risk-first; each = smallest change → predicate on the real artifact → keep/revert, TSV row):
  - U0 profile (browser, W1+W2 build, 2^18+2^20): `stage2_sumcheck` per level + `sumcheck_round` sequence + mode/linear kind/len log line. Predicate: eligible ≥ 0.19 s @2^18 and ≥ 0.6 s @2^20, else KILL.
  - U1 trip probe: 47 dependent RUN_SEQ rounds (1 dispatch + 96 B readback) through the Phase-1 mailbox. Predicate: ≤ 2.0 ms/trip; > 3 ms → QF-only scope (21 trips) re-estimate; > 4 ms → KILL.
  - U2 patch 0008 + CPU reference device (device computes terms with the CPU code): native `test-roundtrip` proof sha unchanged with the device installed — proves hook placement, trimming/SkipLinear on host.
  - U3 RD field round WGSL (fold+eval, dense weights, dense linear) vs Python fp128 oracle (`bench/test_fp128_wgsl.py` pattern, 100k vectors) → browser parity shadow on levels 3–6 → proofs byte-identical 2^16–2^21, verify=true.
  - U4 RD round 0 on compact digits (LUT `CompactPairFoldLut` in-shader) + materialize. Same predicates.
  - U5 QF levels: two-round prefix partials/reduce (Metal `direct_relation_two_round_prefix_*`), alpha/lane weights, partial-lane modes, additional sparse terms. Parity shadow levels 1–2.
  - U6 (conditional) in-kernel linear-term expansion for Packing/Sparse kinds.
  - U7 idle bench `bench_webgpu.py --gpu all` 2^16–2^21 on macbook-home → kill-rule verdict; `--parity` ≥ 6 rounds per level clean.
  - U8 (optional, only if U1 shows trips dominate): resident tail — remaining rounds on-device with a 1-thread Blake2b transcript kernel (Metal `akita_fp128_blake2b_relation_sumcheck_round`, `relation_resident.rs`); needs transcript state export (patch 0010) + grinded-challenge replication; parity = the proof itself.
- Kill early if: U0 eligible < 0.19 s @2^18; U1 > 4 ms/trip; two fix rounds fail to reach byte-identical proofs on any level; U7 increment < 0.078 s @2^18 AND < 0.284 s @2^20.

## Lever 2 — digit-range remainder (after W2's 6 ring rounds on b=8 direct leaves ≥ 2^16 digits)
- Decomposition @2^18 (mini → MBP ms): (16,18) 71 → 32 (product stage arity 2 + class-indexed leaf, `class_indexed_product.rs`/`class_indexed_range_leaf.rs`); (32,17) 54 → 24 (arity 4); (8,19) 107 → 48 — **not a direct leaf**: `PhysicalResponsePlan` is `Some` on the L2 security-route level (`akita-types/src/proof/relation_range_image.rs:55-64`, catalog row num_vars 19 `L2 … physical_response_len 32768`) → `physical_l2_norm` leaf, never seen by the 0007 seam; tails of the 3 GPU'd instances: CPU resumes via `from_materialized` on n/64 tables (2^18 entries @L1, 18 rounds) — not in any trace; bounded by the W2 arithmetic (b=8 CPU ≈ 0.50 s pre-W2 incl. (8,19) → saving 0.447 s ⇒ tails ≈ 0–50 ms).
- Total remainder ≈ 0.10–0.15 s (6–10 %); reachable after GPU cost (3 instances × ~7 trips + product-stage kernels ≈ 40 ms) ≈ 0.06–0.08 s = 4–5 % @2^18; @2^20 tables ×4 → ≈ 0.25–0.35 s = 7–10 %. Three new kernel families (class-indexed product/leaf, L2 norm leaf, x-phase rounds past `ring_bits` — the 0007 seam clamps device rounds to the y-phase) for a saving at the bar. Only cheap sub-lever: raise `CPU_TAIL_BITS` 12 → tune vs Metal's 2^16 cutoff (each dropped trip ≈ 1.5 ms vs ~1–2 ms CPU round at 2^12–2^14) — ±10 ms, noise.
- Profile plan (pending; native is impossible: no CPU digit-range device exists and `digit-range-device` needs `.wasm-deps`, so the W2-after tail only exists in the browser): implementer adds `--dump-trace PATH` to `bench/bench_webgpu.py` (the `get-trace`/`clear-trace` messages already exist, ~10 lines) and `bench/trace_spans.py` (per-name inclusive totals; child `sumcheck_round`/`digit_range_direct_leaf_*` sequences under each `stage2_sumcheck`/`digit_range_prove{basis,rounds}`; the 40-line aggregation used for this plan); run once warm at 2^18 and 2^20 in W1+W2 mode on macbook-home (idle, load1 < 3).
- Kill if: post-W2 CPU under `digit_range_prove` (all instances, minus `[gpu] digit range` wall) < 0.12 s @2^18 and < 0.45 s @2^20. Otherwise order: L2-route leaf (single instance, reuses W2 field kernels + norm term) → b16/32 → tails.

## Lever 3 — commit polish: KILL
- Measured W1 wall (pack+upload+gpu+readback): 2^18 1.6+5.0+24.7+2.0 = **33 ms = 2.1 %**; 2^20 79 ms = 2.2 %; 2^21 145 ms = 2.1 %. Zeroing the entire commit cannot meet 5 %/8 %.
- Codes buffer (T×64 B: 16 MiB @2^18, 128 MiB @2^21): in-kernel hot+mask reads only halve the bytes (hot nibbles 28.5 B/row + mask 8 B) → −1.2 ms @2^18, −10 ms @2^21; kernel 24.7 ms vs 12.7 ms gather floor → ≤ 12 ms (0.8 %). Keep as Phase-1/2 hygiene only: cache the A plane across proves (16 MiB, ≈2.5 ms, UX not perf).

## What CUDA/Metal do differently (applicable → WebGPU)
- Both: one dispatch per round, host owns Fiat–Shamir; split-eq product in-kernel (`jolt_fr_split_eq_dot_partials`: `eq_one[idx>>k]·eq_two[idx&mask]`, block tree reduce, `sum_finish`) — W2 already matches.
- Metal direct range: all rounds on GPU (`backend.rs:672` loop), `COMPACT_PREFIX_ROUNDS = 3` on i8 then field ping-pong, no CPU tail — Metal dispatch ≈ 0.1–0.3 ms vs our ≈ 1.5 ms trip, hence our 2^12 tail. Metal stage-5 tail cutoff = 2^16 elements (`metal/instruction_read_raf.rs:44,55`) — tune ours between 2^12 and 2^16 with U1's trip figure.
- Metal direct relation: prefix on GPU (`two_round_prefix_partials/reduce`), structured linear terms expanded on device (`setup_source`, `sparse_source`) and folded per round (`linear_fold`, `alpha_fold`, `scalar_advance`, `additional_fold`) in the same command buffer; QF-only + `coefficient_rounds ≥ 3` admission; **resident suffix** runs the remaining rounds without host trips using an on-device Blake2b transcript kernel (absorb poly → squeeze challenge → fold) — the only known cure for our trip floor (U8).
- CUDA `instruction_read_raf`: `CHUNK_LEN = 8` address phases — after 8 challenges the host builds `eq_table(phase_challenges)` and the kernel consumes prefix checkpoints instead of re-folding (`instruction_read_raf.rs:1245-1262,1348-1360`) — a round-batching trick for one-hot/sparse tables; not applicable to stage 2's dense fold, relevant to G2.
- Metal decodes 3-bit digits to i8 on host (`decode_digit_witness`, 16 MiB) — we keep packed decode in-shader (W2 already does).

## wasm32 / WebGPU constraints
- wasm peak is already 3.24 GB at 2^21 (W1+W2); stage-2 `FoldedSuffix` = n/2·16 B (64 MiB @2^18 L1, 256 MiB @2^20, 512 MiB @2^21) plus dense weights — moving them GPU-resident lowers wasm pressure, but the CPU still materializes them today; the device must take the compact digits (3 bit) and never receive the dense table.
- GPU: proxy requests adapter-max `maxStorageBufferBindingSize`/`maxBufferSize` (`gpu-proxy.js:316-321`) — log the granted values in U0; 2^21 L1 tables 512+256 MiB need ≥ 1 GiB bindings or split bindings. Mailbox `MAX_REGIONS = 8` is fully used by W2's RUN_SEQ; a stage-2 round needs ~10 (w src/dst, weights src/dst, linear, eq×2, partials, out, additional) → bump to 12 in `mailbox.rs` + `gpu-proxy.js` `W` (layout change, mirror by hand). All indices < 2^32 (tables ≤ 2^27).
