WebGPU repro: silent wrong results from a G1 bucket-accumulation compute kernel at high occupancy

This page dispatches two production WGSL compute kernels (elliptic-curve bucket accumulation over BN254 G1, 16-bit-limb Montgomery arithmetic, pure per-thread — no atomics, no barriers, no workgroup memory) over a deterministic synthetic workload, at a sweep of thread counts, and verifies every output on the CPU with BigInt reference arithmetic. Each output point is a sum of known curve points, so it must (a) be on the curve y² = x³ + 3z⁶, (b) match the CPU-computed value for sampled buckets, (c) be bit-identical across repeat dispatches of identical inputs. On affected configurations (observed: Apple M5 Max × Chrome/Chromium 145) the large dispatches return wrong limbs with zero validation errors, zero device loss — while the same kernels at small dispatch sizes pass, and the same page on other dies (Apple M4) passes at every size.
